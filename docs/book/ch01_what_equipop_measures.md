# 1. What EquiPop measures

## The idea

Ask a person in any town: "what is your neighbourhood?" Nobody
answers with the name of a statistical zone. People experience the
town from where they stand — the nearest streets, the nearest
schools, the nearest thousand people. EquiPop takes that experience
seriously. For **every** person (or grid cell) it builds an
**egocentric neighbourhood**: the k nearest neighbours, counted
outward from that person's own doorstep, and then describes it —
what share belong to some group, what the median income among them
is, how far or how much effort it takes to reach them.

Two consequences follow, and they are the reason this software family
exists. First, **the arbitrary map disappears**: no administrative
border decides who is whose neighbour. Second, the neighbourhood
gets a **size dial**: k = 50 asks about the immediate surroundings,
k = 1,600 about the wider district, k = 25,600 about the town. Any
quantity — a segregation index, a context share, an accessibility
score — becomes a **profile across scales** rather than a single
number frozen at one administrative level. Often the profile IS the
finding: micro-scale sorting that fades by k = 6,400 tells a
different story than sorting that persists.

![Gridby: the context share at k = 400, and the same gradient seen at three scales](figs/ch01_gridby.png)

The figure introduces **Gridby**, the synthetic town used throughout
this book (founded 1848, population ~18,800). Gridby is generated by
a script with *planted* properties — a west–east minority gradient
from 10 % to 60 %, a river with one bridge, a hill, a jobs cluster —
so every figure demonstrates exactly one phenomenon against a known
truth. The right panel shows the signature move: the same planted
gradient read at k = 50 (noisy, local), 400, and 1,600 (smooth,
regional). The dashed line is the truth the town was built with.

## Cook it

```python
from equipop.datasets import load
from equipop.cells import CellData
from equipop.fastcounts import run_knn_counts

g = load("gridby")
p = g["people"]
cd = CellData(E=p.x.to_numpy(), N=p.y.to_numpy(),
              n=p.count_all.to_numpy(),
              binary_sums={"g": p.count_group.to_numpy()},
              value_arrays={}, unit_size=100.0)
out = run_knn_counts(cd, k_values=[50, 400, 1600])
print(out[["EastWest", "NorthSouth", "N_400", "R_g_400"]].head())
```

Four lines of setup, one line of engine. `R_g_400` is each cell's
individualised context share among its 400 nearest residents.

## The dials

`k_values` — as many scales as you like in one run. `unit_size` —
the grid resolution (100 m is the register classic). Everything else
in this book is, in a sense, more dials for this one idea.

## Under the hood

k is defined on **raw counts**, and whole cells enter at once, so
`N_k` (the factual count) can exceed k slightly — it is reported,
never hidden. Equidistant cells form one **atomic ring** (the tie
convention, tolerance 1e-6 m), which makes results deterministic and
direction-symmetric; a legacy mode reproduces the original C#
sequential behaviour. Missing coordinates are dropped **loudly**;
an unreached k yields partial results, never nothing.

## Pitfalls

The scale dial cuts both ways: comparing an R at k = 400 in a dense
city with the same k in a rural area compares different *geographies*
(the radius floats — see chapter 4). That is a feature, but only if
you know it.
